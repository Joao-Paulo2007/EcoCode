# ADR-018: Cadastrar os registros iniciais pelo service

- **Status:** Aceita
- **Data:** 2026-10-22
- **Autores:** Grupo do projeto

## Contexto

Na versão 1.0, os 12 registros de exemplo eram criados com `new Residuos(...)` direto na
lista, dentro do construtor do `Cadastro` (ADR-008). Na refatoração, uma primeira versão
deixou a tela com uma lista própria, e os registros iniciais iam para o repositório enquanto
os cadastros do usuário iam para a lista da tela, o que fazia a listagem mostrar só parte
dos dados.

## Decisão

> Vamos cadastrar os registros iniciais chamando `service.salvar(...)`, para que passem pelas
> mesmas validações e pelo mesmo gerador de código de um cadastro normal.

- São 10 registros, o mínimo da Etapa 1, dois de cada categoria.
- Os tipos e as quantidades ficam em dois arrays percorridos por um laço; cada registro
  recebe uma descrição padrão de teste.
- A tela usa um único service, e o service usa um único repositório, para que todos os
  dados fiquem no mesmo lugar.

## Alternativas consideradas

### Alternativa 1: Criar os objetos direto no repositório

- **Prós:** mais rápido.
- **Contras:** pula as validações e a geração de código do service.
- **Por que não foi escolhida:** os exemplos devem seguir as mesmas regras do cadastro real.

## Consequências

### Positivas

- Os registros iniciais aparecem em todas as telas (listagem, categoria, edição).
- Cobrem as cinco categorias.
- Adicionar um registro é acrescentar um item em cada array.

### Negativas

- Os dados de teste continuam dentro da tela, no construtor.
- Se outra classe criar um `new GerenciarResiduosService()`, ela terá um repositório vazio,
  separado deste.

## Riscos e pendências

- [ ] Remover os registros iniciais quando houver persistência em arquivo.
