# ADR-025: Gerar o código por sequência de cada tipo (último + 5), salvando o último em arquivo

- **Status:** Aceita
- **Data:** 2026-10-24
- **Autores:** Grupo do projeto

## Contexto

O gerador usava um contador único, `static`, que começava em 1 e avançava até encontrar um
número com o resto do tipo (ADR-004, ADR-013). Isso tinha dois problemas:

- Os números pulados ficavam perdidos. Cadastrar um celular (1) e depois um computador
  descartava 2, 3 e 4 para chegar em 5.
- Com os resíduos salvos em arquivo (ADR-024), o contador voltava a 1 a cada execução e
  passava a testar, um por um, códigos já usados.

## Decisão

> Vamos gerar o código de cada tipo a partir do último código daquele mesmo tipo, somando 5,
> e guardar o último código de cada tipo num arquivo JSON próprio.

- O próximo código de um tipo é **último + 5**. Como somar 5 não muda o resto da divisão por
  5, o código continua na categoria certa.
- O primeiro código de cada tipo é o próprio resto (1, 2, 3, 4); para computadores, cujo
  resto é 0, começa em 5, para não usar o código 0000.
- O gerador lê `contadores.json` quando é criado, guarda os valores num
  `EnumMap<TipoResiduo, Integer>` e regrava o arquivo a cada código gerado.
- O formato de 4 dígitos (`%04d`) continua.

Sequências resultantes:

| Tipo | Resto | Códigos |
| --- | --- | --- |
| Computadores | 0 | 0005, 0010, 0015, ... |
| Celulares | 1 | 0001, 0006, 0011, ... |
| Cabos | 2 | 0002, 0007, 0012, ... |
| Baterias | 3 | 0003, 0008, 0013, ... |
| Outros | 4 | 0004, 0009, 0014, ... |

Cada linha é uma **classe de congruência módulo 5**: todos os números que deixam o mesmo
resto na divisão por 5. A regra "último + 5" usa a propriedade a ≡ a + 5 (mod 5).

## Alternativas consideradas

### Alternativa 1: Manter o contador único para todos os tipos

- **Prós:** os códigos refletem a ordem de cadastro.
- **Contras:** desperdiça números e reinicia a cada execução.
- **Por que não foi escolhida:** os dois problemas descritos no contexto.

### Alternativa 2: Calcular o último código de cada tipo a partir dos resíduos salvos

- **Prós:** uma única fonte de verdade; nunca fica dessincronizado.
- **Contras:** percorre todos os resíduos a cada cadastro; um resíduo excluído pode ter o
  código reaproveitado.
- **Por que não foi escolhida:** o grupo preferiu guardar o último valor diretamente.

### Alternativa 3: Reaproveitar a `PersistenciaArquivo` para o arquivo de contadores

- **Prós:** um código de leitura e escrita só.
- **Contras:** ela trabalha com listas (`List<T>`), e os contadores são um mapa.
- **Por que não foi escolhida:** o gerador lê e grava o próprio arquivo.

## Consequências

### Positivas

- Nenhum número é desperdiçado: todos os inteiros acabam sendo usados por algum tipo.
- A sequência continua de onde parou depois que o programa é fechado.
- A geração não precisa de laço; o próximo código é calculado direto.
- A regra é uma aplicação direta de congruência módulo 5, conteúdo da disciplina.

### Negativas

- **Duas fontes de verdade:** `residuos.json` e `contadores.json` podem discordar se um for
  editado ou apagado à mão, ou se o programa fechar entre as duas gravações. Por isso o laço
  do service, que pede outro código se o gerado já existir, foi mantido como proteção.
- O código não indica mais a ordem de cadastro.
- Um código gerado e não usado (por exemplo, se a criação do `Residuo` falhar depois) fica
  perdido, porque o contador já foi gravado.
- Com 4 dígitos, cada tipo tem cerca de 2000 códigos antes de passar de 9999.
- O gerador precisa ser criado uma vez só; duas instâncias teriam cópias separadas dos
  contadores e uma sobrescreveria a outra no arquivo.

### Neutras

- Novo caminho na `Constantes`: `CONTADORES_PATH`.
- Saíram o contador `static` e o laço interno do gerador.

## Riscos e pendências

- [ ] Gravar o contador só depois de o resíduo ser salvo, para não perder códigos quando o
  cadastro falhar.
- [ ] Tratar `JsonSyntaxException` se o `contadores.json` estiver corrompido.

## Referências

- Altera o ADR-013 na forma de gerar o código; o formato de 4 dígitos e a normalização do
  código digitado continuam.
- Mantém a regra do ADR-004: o código continua caindo na categoria do tipo pelo mod 5.
- ADR-024 (salvamento em arquivo). `Util/GerarCodigoResiduo`, `Constantes`.
