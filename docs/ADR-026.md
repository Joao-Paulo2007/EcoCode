# ADR-026: Salvar os usuários em arquivo JSON, reaproveitando a persistência dos resíduos

- **Status:** Aceita
- **Data:** 2026-10-24
- **Autores:** Grupo do projeto

## Contexto

O módulo de usuários (ADR-022) guardava os dados só num `TreeMap` em memória, e o `listar()`
do repositório devolvia sempre uma lista vazia. Os resíduos já passaram a ser salvos em
arquivo JSON por uma persistência genérica, `PersistenciaArquivo<T>` (ADR-024). O login, que
ainda vai ser feito, depende de os usuários continuarem existindo depois que o programa fecha.

## Decisão

> Vamos salvar os usuários num arquivo JSON próprio, usando a mesma `PersistenciaArquivo<T>`
> e o mesmo padrão de repositório dos resíduos.

- O repositório cria a persistência num campo, com `Constantes.USUARIOS_PATH` e
  `Usuario.class`.
- O construtor sem parâmetros carrega o arquivo uma vez e monta o `Map`, usando o CPF como
  chave.
- O `Map` é a fonte principal: `buscar` e `listar` leem só o `Map`; `cadastrar`, `editar` e
  `remover` mudam o `Map` e chamam `gravar()`, que regrava o arquivo inteiro.
- O `listar()` passou a devolver `new ArrayList<>(usuarios.values())`.

## Alternativas consideradas

### Alternativa 1: Uma persistência específica para usuários

- **Prós:** poderia tratar a data de nascimento e a senha de forma própria.
- **Contras:** duplicaria o código de leitura e escrita de JSON.
- **Por que não foi escolhida:** a persistência genérica já resolve, mudando só o caminho e a
  classe.

### Alternativa 2: Guardar usuários e resíduos no mesmo arquivo

- **Prós:** um arquivo só.
- **Contras:** cada mudança num usuário regravaria também todos os resíduos; os dois tipos
  têm campos diferentes.
- **Por que não foi escolhida:** um arquivo por entidade mantém cada repositório
  independente.

## Consequências

### Positivas

- Os usuários sobrevivem ao fechamento do programa, o que é pré-requisito para o login.
- Resíduos e usuários seguem o mesmo padrão; quem entende um entende o outro.
- O `listar()` deixou de devolver uma lista sempre vazia.

### Negativas

- **A data de nascimento impede a gravação.** O `Usuario` guarda um `LocalDate`, e o Gson não
  consegue gravar nem ler `java.time.LocalDate` sozinho nas versões recentes do Java (o
  projeto usa Java 25). Sem um adaptador, o primeiro `cadastrar` lança `JsonIOException`.
- O arquivo guarda CPF, e-mail e data de nascimento em texto legível. São dados pessoais, e o
  `usuarios.json` não pode ir para o repositório do GitHub.
- A senha vai para o arquivo cifrada com a Cifra de César (ADR-023), que é quebrada por força
  bruta.
- O Gson cria o `Usuario` sem chamar o construtor, então a validação do CPF, do nome e do
  e-mail não roda na leitura do arquivo.
- O repositório fica preso ao JSON, como o de resíduos (ADR-024).

### Neutras

- Novo caminho na `Constantes`: `USUARIOS_PATH`.

## Riscos e pendências

- [x] (ADR-029) Registrar um adaptador de `LocalDate` no Gson da `PersistenciaArquivo` (gravando a data
  como texto `AAAA-MM-DD`), ou guardar a data como `String` no `Usuario`.
- [ ] Colocar a pasta de dados (`arquivos/`) no `.gitignore`.
- [ ] Remover o campo `constante = new Constantes()` do repositório; ele não é usado e não
  compila se o construtor da `Constantes` for `private`.
- [x] Normalizar o CPF antes de usar como chave (feito no ADR-027).
