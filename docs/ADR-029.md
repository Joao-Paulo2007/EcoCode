# ADR-029: Data de nascimento em AAAA-MM-DD no arquivo e em DD/MM/AAAA para o usuário

- **Status:** Aceita
- **Data:** 2026-10-24
- **Autores:** Grupo do projeto

## Contexto

O `Usuario` guarda a data de nascimento como `LocalDate`. O Gson não consegue gravar nem ler
`LocalDate` sozinho nas versões recentes do Java (o projeto usa Java 25), o que impedia o
salvamento dos usuários (ADR-026). Além disso, a tela precisava exibir a data no formato
brasileiro sem converter em cada lugar.

## Decisão

> Vamos gravar a data no arquivo como texto no formato AAAA-MM-DD, por meio de um adaptador
> registrado no Gson, e oferecer no `Usuario` um getter que devolve a data já em DD/MM/AAAA.

- **Arquivo:** a `PersistenciaArquivo` registra um `TypeAdapter<LocalDate>` no Gson, que
  grava `data.toString()` (`"2006-05-14"`) e lê com `LocalDate.parse`. Datas nulas são
  gravadas e lidas como `null`.
- **Entrada:** o construtor do `Usuario` recebe a data como texto DD/MM/AAAA e converte com o
  `FORMATTER` `dd/MM/yyyy`.
- **Exibição:** `getDataNascimentoFormatada()` devolve `dataNascimento.format(FORMATTER)`,
  no mesmo formato da entrada.
- `getDataNascimento()` continua devolvendo o `LocalDate`, para contas com datas.

| Onde | Formato | Exemplo |
| --- | --- | --- |
| Digitado pelo usuário | DD/MM/AAAA | 14/05/2006 |
| Dentro do programa | `LocalDate` | |
| Arquivo `usuarios.json` | AAAA-MM-DD | 2006-05-14 |
| Exibido na tela | DD/MM/AAAA | 14/05/2006 |

## Alternativas consideradas

### Alternativa 1: Guardar a data como `String` no `Usuario`

- **Prós:** o Gson grava sem adaptador.
- **Contras:** qualquer conta com a data (idade, data futura) exigiria converter antes; nada
  garantiria que o texto é uma data válida.
- **Por que não foi escolhida:** o `LocalDate` mantém a data validada e pronta para contas.

### Alternativa 2: Gravar no arquivo em DD/MM/AAAA

- **Prós:** o mesmo formato em todo lugar.
- **Contras:** foge do padrão ISO, que é o que o `LocalDate` lê e grava sem configuração.
- **Por que não foi escolhida:** o formato de exibição fica na tela; o arquivo usa o padrão.

### Alternativa 3: Getter de data devolvendo `String` no lugar do `LocalDate`

- **Prós:** um getter só.
- **Contras:** perde o `LocalDate` para cálculos.
- **Por que não foi escolhida:** os dois getters atendem usos diferentes.

## Consequências

### Positivas

- Os usuários passam a ser salvos e lidos do arquivo.
- A tela exibe a data sem converter.
- O adaptador está na persistência genérica e vale para qualquer classe com `LocalDate`.

### Negativas

- Dois formatos de data no projeto, um para o arquivo e outro para o usuário.
- Um texto de data inválido editado à mão no arquivo lança `DateTimeParseException` na
  leitura.

### Neutras

- O Gson grava os campos, não os getters, então o getter formatado não aparece no arquivo.

## Riscos e pendências

- [ ] Impedir data de nascimento futura (pode usar `getDataNascimento()` com
  `LocalDate.now()`).
