# ADR-008: Carregar 12 registros de exemplo no construtor do Cadastro

- **Status:** Substituída por ADR-018
- **Data:** 2026-10-06
- **Autores:** Grupo do projeto (versão 1.0 publicada por João Paulo)

## Contexto

A Etapa 1 exige que o programa trabalhe com pelo menos 10 registros. Como os dados ficam
só em memória (ADR-003), digitar 10 cadastros a cada execução tornaria testes e
apresentação lentos.

## Decisão

> Vamos cadastrar automaticamente 12 resíduos, um para cada exemplo do enunciado, no
> construtor do `Cadastro`, usando o mesmo gerador de código do cadastro normal.

Itens: Notebook, Computador, Celular, Tablet, Bateria, Pilha, Cabo, Monitor, Teclado,
Mouse, Impressora e Carregador, com quantidades fixas.

## Alternativas consideradas

### Alternativa 1: Usuário cadastra tudo manualmente

- **Prós:** nenhum dado "de mentira" no programa.
- **Contras:** 10 cadastros a cada execução.
- **Por que não foi escolhida:** inviável para testar e apresentar.

### Alternativa 2: Opção no menu para carregar exemplos

- **Prós:** o programa pode começar vazio quando necessário.
- **Contras:** um passo a mais na apresentação.
- **Por que não foi escolhida:** começar já com dados atende a Etapa 1 sem esforço.

## Consequências

### Positivas

- O requisito de 10 registros é cumprido assim que o programa abre.
- Os 12 itens cobrem as cinco categorias, então a opção de classificação já mostra todos
  os restos de 0 a 4.
- Como passam pelo `gerarCodigo`, os exemplos seguem as mesmas regras do cadastro real.

### Negativas

- Dados de teste ficam misturados com o código de produção, dentro do construtor.
- Não há como iniciar o programa vazio.
- Os registros iniciais pulam a tela e, portanto, qualquer validação que um dia for
  colocada só nela.

## Riscos e pendências

- [ ] Separar os dados de exemplo antes de incorporar o módulo ao app do grupo.
