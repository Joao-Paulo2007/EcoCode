# ADR-007: Classificar com uma classe utilitária estática

- **Status:** Substituída por ADR-015
- **Data:** 2026-10-06
- **Autores:** Grupo do projeto (versão 1.0 publicada por João Paulo)

## Contexto

A Etapa 2 pede que o programa mostre, para cada código, a classe calculada (o resto) e a
categoria correspondente na tabela de restos. A regra não depende de nenhum estado: o
mesmo código sempre dá o mesmo resultado.

## Decisão

> Vamos reunir a classificação na classe `Classificador`, com métodos `static`, separada
> do cadastro.

| Método | Faz |
| --- | --- |
| `obterRestoPorTipo(String tipo)` | Nome do resíduo para o resto da categoria (ADR-006) |
| `calcularResto(String codigo)` | `Integer.parseInt(codigo) % 5` |
| `classificar(String codigo)` | Resto para o nome da categoria, via `switch` |

A opção 4 do menu mostra código, resíduo, quantidade, resto e categoria de cada registro,
como no exemplo do enunciado.

## Alternativas consideradas

### Alternativa 1: Interface `Classificador` com implementações (por código, por tipo)

- **Prós:** permitiria comparar, lado a lado, classificar pelo código e pelo tipo, que é
  a discussão pedida no "Atenção".
- **Contras:** mais classes.
- **Por que não foi escolhida:** com o código derivado do tipo (ADR-004), as duas
  classificações sempre coincidem.

### Alternativa 2: Calcular dentro do `Cadastro`

- **Prós:** um arquivo a menos.
- **Contras:** misturaria a regra matemática com a tela.
- **Por que não foi escolhida:** manter o cálculo isolado deixa a parte avaliada pela
  disciplina fácil de mostrar.

## Consequências

### Positivas

- A aritmética modular fica num lugar só, fácil de apresentar e de testar.
- O cálculo real de k mod 5 aparece explicitamente em `calcularResto`.

### Negativas

- A tabela de categorias está repetida de forma implícita em dois métodos
  (`obterRestoPorTipo` e o `switch` de `classificar`); mudar uma categoria exige mexer nos
  dois.
- `calcularResto` lança `NumberFormatException` se receber um código não numérico.
