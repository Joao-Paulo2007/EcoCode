# ADR-006: Receber o tipo do resíduo como texto livre, reconhecido por sinônimos

- **Status:** Substituída por ADR-012
- **Data:** 2026-10-06
- **Autores:** Grupo do projeto (versão 1.0 publicada por João Paulo)

## Contexto

O enunciado lista resíduos como notebook, celular, bateria, cabo e impressora, e as cinco
categorias da Etapa 2. O usuário precisa informar o que está descartando, e o sistema
precisa saber em qual categoria isso cai para gerar o código (ADR-004).

## Decisão

> Vamos deixar o usuário digitar o nome do resíduo livremente e mapear esse texto para
> uma categoria comparando com uma lista de nomes e sinônimos conhecidos.

`Classificador.obterRestoPorTipo` converte o texto para minúsculas, tira os espaços das
pontas e compara com listas fixas. Por exemplo, "pc" e "desktop" contam como
computador; "fone", "headset" e "carregador" contam como periférico. O que não está em
nenhuma lista vai para 4, Outros eletrônicos. O texto digitado é guardado como foi
escrito, no campo `tipo_residuo`.

## Alternativas consideradas

### Alternativa 1: Menu fechado com as categorias (enum)

- **Prós:** sem erro de digitação; o código não depende de comparar textos.
- **Contras:** perde o nome específico do item ("fone bluetooth" vira só "Cabos e
  periféricos").
- **Por que não foi escolhida:** o grupo quis registrar o nome real do resíduo.

## Consequências

### Positivas

- O usuário escreve do jeito natural, e a listagem mostra o nome exato do item.
- Maiúsculas e espaços extras não atrapalham.

### Negativas

- Erro de digitação muda a categoria sem aviso: "celulr" vira Outros eletrônicos.
- Variações não previstas também caem em Outros ("impressora 3d", "smartwatch").
- Cada sinônimo novo exige editar o `if/else` do `Classificador`.
- Texto vazio é aceito e cadastrado como Outros.

## Riscos e pendências

- [ ] Avaliar trocar por um enum de tipos com menu numérico, mantendo um campo de
  descrição livre para o nome específico.

## Referências
