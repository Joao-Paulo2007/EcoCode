# ADR-016: Editar e excluir por código, com confirmação e sem alterar tipo nem código

- **Status:** Aceita
- **Data:** 2026-10-23
- **Autores:** Grupo do projeto

## Contexto

A versão 1.0 só cadastrava e listava. A refatoração acrescentou edição e exclusão. O código
do resíduo é gerado a partir do tipo para que o mod 5 caia na categoria certa (ADR-004),
então mudar o tipo de um resíduo já cadastrado quebraria essa relação.

## Decisão

> Vamos editar e excluir pelo código, sempre mostrando o resíduo e pedindo confirmação
> (s/n) antes, e permitir editar só a quantidade e a descrição.

- **Editar:** o usuário vê o resíduo, confirma, e pode apertar Enter para manter a
  quantidade ou a descrição atual. Tipo e código não são editáveis.
- **Excluir:** o usuário vê o resíduo e confirma antes de remover.
- O service usa o próprio `buscar`, que normaliza o código e lança erro se não encontrar
  (ADR-013, ADR-014). O `editar` devolve o resíduo atualizado para a tela exibir.

## Alternativas consideradas

### Alternativa 1: Permitir editar o tipo

- **Prós:** corrige um tipo escolhido errado sem excluir.
- **Contras:** o código antigo deixaria de corresponder à categoria no mod 5.
- **Por que não foi escolhida:** para trocar o tipo, basta excluir e cadastrar de novo, e o
  código novo é gerado corretamente.

### Alternativa 2: Agir direto, sem confirmação

- **Prós:** um passo a menos.
- **Contras:** um código digitado errado apagaria ou alteraria o resíduo errado.
- **Por que não foi escolhida:** mostrar o resíduo antes evita engano.

## Consequências

### Positivas

- A relação entre código e categoria nunca é quebrada por uma edição.
- Enter para manter o valor deixa a edição rápida.
- A quantidade na edição é lida com `nextLine()` e convertida, e letra digitada mostra uma
  mensagem em vez de derrubar o programa.

### Negativas

- Trocar o tipo exige excluir e recadastrar, o que gera um código novo.
- A exclusão não pode ser desfeita.
