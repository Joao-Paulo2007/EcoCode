# ADR-045: Mostrar as opções de usuários no menu só para o gerente, numa tela própria

- **Status:** Aceita
- **Data:** 2026-10-28
- **Autores:** Grupo do projeto

## Contexto

O cadastro de usuários já era restrito a gerentes no service (ADR-022), mas não existia
nenhuma tela para cadastrar ou listar usuários: só dava para fazer isso pelo código do
`Main`. Com o login (ADR-043), a tela de resíduos passou a saber quem está usando e qual o
cargo dessa pessoa.

## Decisão

> Vamos mostrar no menu de resíduos as opções "Cadastrar um usuário" e "Listar usuários"
> apenas quando o usuário logado for gerente, e colocar essas opções numa tela separada,
> `TelaGerenciarUsuariosTerminal`.

**Menu**

| Opção | Quem vê |
| --- | --- |
| 1 a 6 (resíduos) | Todos |
| 7 - Sair | Todos |
| 8 - Cadastrar um usuário | Só gerente |
| 9 - Listar usuários | Só gerente |

- O menu mostra no topo o nome e o cargo de quem está logado.
- O cargo é conferido uma vez, antes do loop do menu (`ehGerente`), porque não muda durante a
  sessão.
- Um funcionário que digitar 8 ou 9 recebe "Opção inválida", como se a opção não existisse.
- O 7 continuou sendo Sair, para não mudar o número que o grupo já usava.

**`TelaGerenciarUsuariosTerminal`**

| Método | Faz |
| --- | --- |
| `cadastrarUsuario()` | Pede nome, CPF, e-mail, senha, data de nascimento e cargo (1 = gerente, 2 = funcionário) e chama o `service.cadastrar`, passando o cargo de quem está logado |
| `listarUsuarios()` | Mostra nome, CPF, e-mail, cargo e nascimento de cada usuário. A senha não aparece, nem cifrada |

**Duas travas.** A tela esconde as opções, e o `service.cadastrar` continua recusando quem
não é gerente (`AcessoNegadoException`). Se a checagem da tela falhar, o service ainda barra.

## Alternativas consideradas

### Alternativa 1: Colocar os métodos de usuário dentro da `TelaCadastroResiduoTerminal`

- **Prós:** nenhuma classe nova.
- **Contras:** a tela de resíduos passaria a cuidar de dois assuntos e ficaria ainda maior.
- **Por que não foi escolhida:** cada tela cuida de um assunto.

### Alternativa 2: Um menu separado para o gerente, antes do menu de resíduos

- **Prós:** separa bem as áreas.
- **Contras:** mais uma tela de navegação; o gerente também usa as opções de resíduos.
- **Por que não foi escolhida:** acrescentar duas opções ao menu existente é mais simples.

### Alternativa 3: Mostrar as opções para todos e deixar só o service recusar

- **Prós:** nenhuma checagem na tela.
- **Contras:** o funcionário veria opções que nunca vai conseguir usar.
- **Por que não foi escolhida:** a tela deve mostrar só o que a pessoa pode fazer.

## Consequências

### Positivas

- O gerente cadastra e lista usuários pelo próprio programa.
- A regra de acesso fica no service; a tela só adapta o que aparece.

### Negativas

- Ainda não há telas para editar ou remover usuários, embora o service já tenha esses métodos.
- A opção 7 (Sair) aparece depois da 8 e da 9 no menu do gerente.

### Neutras

- Para não confundir com a tela de login (`TelaUsuarioTerminal`), a tela de gestão foi
  nomeada `TelaGerenciarUsuariosTerminal`.

## Riscos e pendências

- [ ] Criar as opções de editar e remover usuário para o gerente.
- [ ] Decidir se excluir resíduos também deve ser só do gerente.
- [ ] Considerar trocar Sair para 0, deixando as opções em sequência.
