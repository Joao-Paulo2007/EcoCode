# ADR-004: Gerar o código de forma que código mod 5 caia na categoria do tipo

- **Status:** Aceita
- **Data:** 2026-10-06
- **Autores:** Grupo do projeto (versão 1.0 publicada por João Paulo)

## Contexto

A Etapa 2 classifica cada resíduo por h(k) = k mod 5, em que k é o código. O próprio
enunciado alerta que isso tem "finalidade didática" e pede que o grupo discuta se, no app
real, a categoria deveria vir do tipo de material.

Com códigos escolhidos livremente, a classificação dá errado. Os exemplos do enunciado
mostram isso: 1027 (Notebook) cai em 2, Cabos; 2048 (Celular) cai em 3, Baterias; 3157
(Bateria) cai em 2, Cabos.

## Decisão

> Vamos gerar o código automaticamente, avançando um contador até encontrar um número
> cujo resto da divisão por 5 seja o resto da categoria do tipo informado.

```java
int restoDesejado = Classificador.obterRestoPorTipo(tipo);
while (codigo_numerico % 5 != restoDesejado) {
    codigo_numerico++;
}
return String.format("%06d", codigo_numerico++);
```

O contador é `static`, começa em 1 e só avança. O usuário não digita o código. Com os
registros iniciais, os códigos gerados são 5 e 10 (resto 0), 11 e 16 (resto 1), 27, 32,
37, 42 e 47 (resto 2), 18 e 23 (resto 3) e 44 (resto 4).

## Alternativas consideradas

### Alternativa 1: Usuário digita o código

- **Prós:** reproduz exatamente os exemplos do enunciado (1027, 2048, 3157).
- **Contras:** a classificação por mod 5 erra na maioria dos casos; o usuário pode repetir
  códigos.
- **Por que não foi escolhida:** o resultado da Etapa 2 seria quase sempre incorreto.

### Alternativa 2: Código sequencial simples (1, 2, 3...)

- **Prós:** trivial.
- **Contras:** as categorias se repetiriam em rodízio (1, 2, 3, 4, 0...), sem relação com
  o resíduo.
- **Por que não foi escolhida:** mesma falha da alternativa 1.

## Consequências

### Positivas

- A classificação por mod 5 sempre bate com o tipo, e o programa cumpre a Etapa 2.
- O código nunca se repete enquanto o programa está aberto.
- Responde à pergunta do "Atenção" na prática: a classificação só funciona porque o
  código é derivado do tipo, ou seja, quem decide a categoria é o tipo.

### Negativas

- O mod 5 deixa de classificar de verdade; ele só confirma o que o tipo já definiu.
- A sequência tem buracos (de 1 pula para 5, depois 10), o que pode parecer erro.
- O contador `static` reinicia em 1 a cada execução; com persistência, geraria códigos
  repetidos.
- Se o tipo de um resíduo mudar, o código antigo deixa de corresponder à categoria.

## Riscos e pendências

- [ ] Registrar no relatório a discussão pedida pelo "Atenção", usando esta decisão como
  argumento.
- [ ] Se houver persistência, iniciar o contador a partir do maior código salvo.
